Business Logic Preserved

FeatureImplementation
3-pass fuzzy name matchingExact substring → token (min 3/4 chars) → fuzzy score ≥ 1
Intent detection18 add-keywords · 12 delete-keywords · 11 report-keywords · 4 all-employees
Add wizard FSMIDLE→NEED_EMP?→NEED_TYPE→NEED_START→NEED_END→CONFIRM→SAVED/CANCELLED
Delete wizard FSMDELETE_IDLE→…→DELETE_CONFIRM→DELETED/CANCELLED + working-day coverage check
By-month distributionProportional overlap: days × overlap_days / total_days
Streak calculationSort + merge with gap ≤ 2 calendar days (bridge weekends)
Month-filter optimizationRestrict by_month + by_type when month mentioned in question
Excel conflict checkPre-write cell scan → ExcelWriteConflictException(date, code)
Atomic file writesWrite to .{uuid}.tmp, rename with 3× retry + exponential backoff
Weekend exclusiondayOfWeek.getValue() > 5 → skip read and write
Working copy / master syncDaemon thread polls every 5 s, wakes on triggerSync()
LLM groundingSystem prompt forbids external knowledge, injects full JSON context
Conversation historyLast 20 messages (10 turns) on AppState
Watsonx supportproject_id added to URL query + request body when set
HTML report generationKPI cards + monthly chart (Chart.js CDN) + type table + detail table
Audit logJSONL append with ReentrantLock — never propagates failures

Frontend (TypeScript SPA)

  • Single IIFE compiled from holiday_agent.ts → holiday_agent.js
  • Boot: 3 parallel fetches — /api/employees, /api/years, /api/files
  • Upload: click-to-browse, drag-and-drop, input.change
  • Chat types: text (markdown render), report (clickable link), vacation_prompt (accent border)
  • Quick chips: 6 templates populated with first employee + selected year
  • Collapsible sidebar sections; swipe-left-to-close on mobile
  • Mobile responsive: hamburger + overlay + sidebar slide at ≤ 768px
  • Auto-resizing textarea, Enter-to-send, Shift+Enter for newline
